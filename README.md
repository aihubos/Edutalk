# EDU톡 PWA MVP

동탄 교육기관·튜터 탐색, 교육자 일터 후기, 학생 성적·성장 관리를 하나로 묶은 모바일 우선 PWA입니다. 현재 실행본은 화면과 계정·운영 연결 기반을 포함하지만, 공개 상용 서비스가 아닙니다.

## VPS 체험 앱

모바일 앱 주소: https://edutalk.ai-hub-os.com

2026-10-19 모바일 디자인을 기존 토스 블루로 반영한 Next.js 앱입니다. 현재는 demo 모드이며, 기관·후기·성적은 체험 데이터입니다. 실제 로그인·공식 데이터·AI·결제는 아직 연결되지 않았습니다. 체험 입력은 이 브라우저에만 저장됩니다. 운영 설정은 [VPS 배포 안내](./deploy/vps/README.md), 디자인 변경은 [모바일 디자인 반영](./docs/design/2026-10-19-mobile-blue.md)을 참고하세요.

## 바로 실행

Node.js 22와 pnpm 10 기준입니다.

macOS에서는 [`EDU톡_실행.command`](./EDU톡_실행.command)를 더블클릭하면 됩니다. 이미 실행 중이면 브라우저만 열고, 처음 실행이면 필요한 패키지를 준비한 뒤 로컬 앱을 엽니다.

```bash
pnpm install
pnpm dev
```

브라우저에서 `http://localhost:3000`을 엽니다. 운영 빌드는 다음과 같습니다.

```bash
pnpm build
pnpm start
```

같은 와이파이에 연결된 휴대폰에서는 Mac에서 `pnpm start`를 실행할 때 표시되는 `Network` 주소로 접속할 수 있습니다. Mac에서 EDU톡이 실행 중이어야 하며, 네트워크 주소는 접속할 때마다 바뀔 수 있습니다.

공개 GitHub Pages 프리뷰는 `https://aihubos.github.io/Edutalk/`에서 볼 수 있습니다. 이 주소는 서비스 방향과 모바일 화면을 보여주는 정적 페이지이며 로그인·AI·성적 저장·메시지·결제는 제공하지 않습니다. 실제 앱 기능은 별도 서버와 Supabase 연결 뒤에 배포합니다.

한 번에 전체 로컬 점검을 실행하려면 `pnpm verify`를 사용합니다. 저장소에 올린 뒤에는 [자동 점검 설정](./.github/workflows/verify.yml)이 같은 타입·코드 규칙·운영 빌드·공공데이터 dry-run을 실행합니다.

실제 공개 전에는 `pnpm release:check`를 실행합니다. 필수 외부 연결·공식 데이터·법률 검토·비공개 베타·백업·모니터링 중 하나라도 확인되지 않으면 실패하며, 어떤 준비가 남았는지 JSON으로 보여줍니다. 법률·베타·백업·모니터링과 공식 데이터는 단순 환경값만으로 통과하지 않고 [`release-evidence.example.json`](./docs/release-evidence.example.json) 형식의 담당자·날짜·증빙 기록도 필요합니다.

## 완료된 화면과 기반

- 최초 실행 시 연령대·필수 정책 요약·역할·지역을 고르고 이용약관·개인정보·커뮤니티 문서 버전을 각각 기록하는 온보딩
- 만 14세 미만은 보호자 아래 자녀 프로필로 전환하고 학생 역할 직접 선택을 제한하는 체험 규칙
- 시작 화면의 두 경로: `아이에게 좋은 배움`, `교육자에게 좋은 일터`. 교육자 일터 경로는 기본 진입으로 두고, 홈의 교육자 만족도는 학생 배움환경을 판단하는 신호일 뿐 결과를 보장하지 않는다고 안내
- 학부모·학생·선생님 역할 전환과 역할별 메뉴
- 동탄1·2 기관 검색, 정렬, 통학차량·체험수업 필터, 상세, 전화·길찾기·문의
- 동탄 생활권·통학 참고·셔틀 권역·모집 상태·항목별 비용·최근 변경 이력의 체험형 상세 데이터. 계정 모드는 공개 승인된 생활권·법정동·행정동·주거권·학교·유치원·주거 단지 기준 출발지 거리만 별도로 표시
- 역할별 최소 프로필을 기준으로 한 demo 추천과 추천 이유 표시, MY에서 계정·체험 추천 프로필 수정
- 최대 3곳 비교, 즐겨찾기, 구조화 후기 초안. 계정 모드의 비교 목록과 관심 기관은 서버에 저장
- 자주 확인하는 동탄1·2 기관 검색 조건을 이름 붙여 최대 10개까지 저장하고 다시 여는 흐름. canonical 기관은 이름·지역·유형과 이름순·최근 확인일순 조건을 함께 저장
- 교육자 일터 후기는 공개 작성자 정보를 숨기는 익명 표시 흐름과 최소 3건의 확인된 후기 뒤 공개 점수 원칙
- 학생 후기는 시간대·학교에서 이동·수업 분위기·숙제 부담·반 인원·설명 방식·레벨테스트 도움·또래 구성·자습공간·시험대비의 10개 핵심 항목과 이해도·수업 속도·동기·이동 편의의 4개 학습 체감 보조 항목을 모두 작성하는 구조
- 학생·학부모·교육자 점수를 서로 섞지 않는 기관 상세·순위 표시와 광고 없는 기관·일터·튜터 순위. 순위는 권역·기관 유형으로 좁히고 기관 상세로 이동할 수 있음
- 로그인한 학부모는 관계 인증 전에도 승인 학부모 후기의 장점만 최대 2건·각 180자 이내로 보는 베타 미리보기; 개선점·추천 대상·상세 내용은 인증 뒤에만 열림
- 학생 고유 ID별 내신·모의고사·수능형 과목점수·총점 그래프와 성장기록
- 교사가 학생을 직접 등록하고 성적·성장기록을 추가, AI 학생일지·생기부 검토용 초안을 만든 뒤 확인하는 흐름
- AI는 계정당 무료 10회와 유료 무제한 플랜을 제공할 결제 진입·상태 표시 코드까지 준비했으며, demo에서는 화면 미리보기만 제공
- 학생별 학부모-교사 알림·메시지, 읽음·중요 표시·이미지 첨부, 교사 확인 뒤 AI 학생일지 공유 흐름
- 교사 계정은 확정된 최근 `JOURNAL` 초안 최대 5개를 학생별로 선택·미리보기하고, 보호자 공유 확인 뒤에만 `sharedAiDraftId`와 함께 알림장으로 전송
- 튜터 프로필·구인글 양방향 등록, 표시명·과목·소개·활동 동네와 구인글 제목·본문·과목·지역을 함께 찾는 통합 검색, 튜터에게 온 실제 계정 문의 응답 결과 기반 응답률, EDU톡 수업 확인 후기 기반 순위, 사진 후기 첨부 흐름
- 본인·자격 인증 튜터가 발급하는 12자리·7일·1회용 수업 확인 코드. 코드 원문은 저장하지 않고, 0.5점 단위 후기는 운영자 승인 전 비공개
- 튜터 신원·자격 증빙을 강하게 요청하는 흐름. 증빙 원본은 공개하지 않고 비공개 심사 자료로 다룰 원칙
- 이용·근무 관계와 튜터 인증, 기관 정보 정정, 콘텐츠 신고 접수·상태 확인 흐름. 기관 관계 신청 중 이해관계 충돌은 별도 검토 큐로 보냄
- 승인된 기관 관계자의 공식 답변, 후기 작성자의 공개 내리기, 열람자의 개인 숨김, 신고 뒤 임시숨김·복원 흐름. 공개 상세에는 정정 최종 결과와 기관 대상 신고의 임시·최종 처리 타임라인만 안전한 요약으로 표시
- 보호자 계정의 자녀 별칭·학년 프로필 관리와 선택적 학습기록 연결. 연결 후 성적·알림장에도 같은 별칭을 사용하며, 실명·학교명·생년월일은 받지 않음
- 고객센터 문의와 튜터 문의·구인 지원 요청의 demo/계정 저장 기반, 운영자 답변 화면
- 운영자용 기능 중지 스위치, 데이터 동기화·품질 큐, 최근 운영 지표·감사 이력, 연결 상태 화면
- 이용약관·개인정보 처리방침·커뮤니티 정책의 출시 전 검토 초안 3종
- 역할별 교육 정책·프로그램·행사 큐레이션과 공식 원문 연결
- DATA_OPERATOR·ADMIN이 공식 원문, 기준일, 역할, 공개 여부를 검수해 정책·행사를 등록·수정하는 운영 화면
- DATA_OPERATOR·ADMIN이 canonical 기관의 비용·셔틀·모집·프로그램·변경 이력을 출처·확인일과 함께 등록하고 공개 여부를 정하는 운영 화면
- DATA_OPERATOR·ADMIN이 canonical 기관의 생활권·법정동·행정동·주거권·기준 출발지 거리와 필드별 출처·확인주체·신뢰등급을 출처·확인일과 함께 공개 승인하는 운영 화면
- 공식 파일 importer는 UTF-8·CP949 CSV/TSV와 UTF-8 JSON을 읽어 학원·교습소를 분리하며, 정상·개원 상태만 공개 후보로 둔다. 휴원·폐원·상태 불명과 반송동·석우동의 좌표 미확정 행은 품질 큐에서 확인한다.
- demo와 canonical 기관 목록은 공개 좌표가 있을 때 위치 도식으로 함께 보며, 지도 타일·통학시간·이동 경로는 표시하지 않습니다. 좌표 없는 기관은 목록에서 계속 확인합니다.
- 오산동은 2026-03-01 이후 여울동으로 정규화해 과거 공식 원본과 함께 처리한다. PWA는 독립 정적 offline fallback을 제공하지만, 오프라인 중 입력·저장·메시지·결제는 서버에 반영되지 않는다.
- 상용 canonical 외부 후기는 DATA_OPERATOR·ADMIN이 확인한 HTTPS 원문 링크와 확인일, `LINK_ONLY`·`UNAVAILABLE` 상태만 관리·공개합니다. 외부 평점·후기 수·본문은 수집·스크래핑·합산하지 않고 EDU톡 점수·순위에 반영하지 않음
- 설치형 PWA 메니페스트, 아이콘, 운영 빌드의 서비스 워커와 설치 버튼. iOS Safari는 공유 → 홈 화면에 추가, 기타 브라우저는 앱 설치 또는 홈 화면에 추가 안내
- ADMIN만 서울 기준 월요일 주차로 실제 주간 순위를 확정하며, 같은 주차를 다시 확정하면 기존 스냅샷을 덮어씀. 연속 두 회차 이상 있을 때만 순위의 상승·하락·신규 표시

## 계정 모드와 AI 연결

`.env.local`에 키를 넣으면 OpenAI Structured Outputs로 초안을 생성합니다.

```bash
OPENAI_API_KEY=...
OPENAI_JOURNAL_MODEL=gpt-5.6
```

키가 없으면 입력한 관찰 사실만 정리하는 규칙 기반 체험 템플릿을 사용하고, 화면에 생성 방식을 따로 표시합니다. 호출은 `store: false`로 설정됩니다.

## 운영 DB 기반

[`supabase/migrations/20260813031052_student_learning_and_tutors.sql`](./supabase/migrations/20260813031052_student_learning_and_tutors.sql)에 학생·보호자·교사 연결, 성적·성장·AI 초안, 튜터·자격 증빙·후기, 기관 후기, 학부모-교사 소통, 인증·정정·신고·열람권·감사·데이터 품질 스키마와 행 단위 접근 규칙이 준비되어 있습니다. 실제 Supabase 프로젝트는 아직 연결되지 않았고, 마이그레이션도 적용되지 않았습니다.

공식 `@supabase/ssr` 기반의 브라우저·서버 클라이언트, OAuth 콜백, 세션 갱신 proxy와 Supabase 계정 연결 화면을 준비했습니다. 프로젝트를 설정하고 마이그레이션을 적용한 계정 모드에서는 다음 데이터를 Supabase로 저장·조회하도록 연결했습니다.

- 교사가 등록한 학생, 평가, 과목 점수, 성장기록
- AI 초안 생성 전에 로그인한 선생님의 활성 담당 학생 연결을 확인하고, 서버의 학생 별칭·학년을 사용
- 교사가 발급한 학생 본인(만 14세 이상) 또는 보호자용 12자리·30분·1회용 연결 코드와 연결된 대화방
- 교사 확인 AI 학생일지·생기부 초안, 메시지의 본문·읽음·중요 표시·이미지 첨부
- 튜터 프로필·구인글·심사 대기 후기와 비공개 사진 첨부, 튜터 문의·구인 지원 요청, 기관 후기의 `PENDING` 접수. 튜터 후기는 12자리 수업 확인 코드의 digest만 7일 보관하고 1회 사용하며, 0.5점 단위 평가와 운영자 승인 뒤에만 공개
- 인증·기관 정정·콘텐츠 신고·고객센터 요청과 본인 상태 이력, 계정 즐겨찾기, 탈퇴 요청
- 비공개 Storage의 인증 증빙(PDF·JPG·PNG, 5MB 이하), 튜터 후기 사진과 메시지 이미지 첨부. 인증 원본은 운영자 전용 5분 만료 링크로만 확인
- 실제 operator role과 운영자 콘솔/API 기반의 인증 승인·반려, 증빙 필수 인증 승인, 승인된 관계 인증의 역할별 6개월 열람권 부여, 튜터 수업 확인 후기 승인, 역할 충돌 별도 검토, 후기 처리 흐름
- 공개 canonical 상세의 비용·셔틀·모집·프로그램·생활권·출발지 거리·필드별 신뢰등급과, 개인정보·작성자·증빙·원문을 제외한 정정·기관 대상 신고 공개 처리 타임라인
- 기관 공식 답변의 수정 이력, 계정별 약관 문서 버전 동의 이력
- 계정 알림 자동 생성·본인 읽음 처리·유형별 수신 설정, 고객센터·튜터 문의의 운영자 답변 저장
- 학생별 알림장 새 메시지·확인 일지의 상대방 알림, 관심 기관 후기·공식 답변·모집 변경 알림, 저장 검색 신규 기관 알림, 복수 담당 교사별 보호자 대화방 생성
- 계정별 최대 3곳 기관 비교, 보호자 자녀 별칭·학년 프로필, 기관 관계 신청·공식 답변, 후기 공개 내리기·개인 숨김
- ADMIN 기능 중지 스위치와 운영 지표, DATA_OPERATOR의 동기화·품질 큐, 공개 최소 상태 확인 API
- ADMIN의 실제 계정 삭제와 관련 데이터 정리 기반. 서버 전용 서비스 키가 필요함
- 인증 심사 종료 뒤 30일 원본 보관 만료일을 기록하고, ADMIN이 만료 파일을 비공개 Storage에서 정리하는 API
- Stripe Checkout·Customer Portal·계정 구독 상태 조회, 서명 웹훅과 `ACTIVE`/`PAST_DUE`/`CANCELED` DB 상태를 AI 무제한 권한으로 반영하는 코드

공식 기관 자료는 유치원알리미의 수동 공시자료 파일과 NEIS 학원·교습소 파일 확보 경로를 확인했습니다. 어린이집은 현재 공식 서비스키 기반 API가 확정 경로입니다. 원본 파일은 아직 내려받거나 운영 DB에 적재하지 않았습니다.

AI 무료 10회 또는 활성 무제한 플랜은 서버 함수 기반으로 판정합니다. 기관 공개 점수는 승인된 후기 숫자만 집계하고, 교육자 일터 점수는 승인된 교사 후기 3건 이상일 때만 표시합니다. `pnpm data:sync:dry-run`은 공공데이터 형식의 고정 fixture를 정규화해 canonical DB 적재 형식을 미리 보는 읽기 전용 점검입니다.

## 로그인과 온보딩 순서

- **Supabase가 설정된 상용 모드:** 로그인 → 약관·연령 확인 → 대표 역할·지역 선택 → 최소 프로필 입력 → 홈
- **Supabase가 미설정된 demo 모드:** 계정 없이 체험 온보딩 → 연령·정책 요약·역할·지역 선택 → 홈

로그인 UI와 Supabase SSR 연결 코드는 준비됐지만, 실제 공급자 설정과 로그인 검증은 아직입니다. Google·Kakao·이메일 로그인도 프로젝트와 공급자 설정 뒤에만 실제로 동작합니다. 네이버 로그인은 OIDC 공급자 연결이 아직 되지 않아 안내만 표시합니다.

## 게스트 공개 경로와 로그인 필요 기능

계정 또는 온보딩 완료 전에도 다음 공개 화면은 둘러볼 수 있습니다: 홈, 기관찾기, 기관 상세, 랭킹, 튜터, 정책·행사, 기관 비교.

성적관리, AI 학생일지·생기부, 학부모-교사 메시지, 후기 작성, 인증·정보정정·신고, MY는 개인 기능입니다. 온보딩을 완료하지 않은 게스트가 접근하면 `/login`으로 이동합니다. 운영 관리자 화면은 production 내비게이션에 넣지 않으며 demo에서만 별도 확인합니다.

## 외부 설정·실운영 미완료

- Supabase 프로젝트, 환경변수, 실제 Auth/OAuth 공급자 연결 및 마이그레이션 적용은 아직 하지 않았습니다. 위 계정·운영자 콘솔/API 기능은 이 연결이 완료된 뒤에만 실제로 동작합니다. 네이버 OIDC도 미연결 상태입니다.
- ADMIN 주간 순위 확정·같은 주차 덮어쓰기와 순위 변동 표시는 내부 코드 기반이며, 실제 Supabase 프로젝트와 마이그레이션 적용 전에는 작동하지 않습니다.
- 비공개 Storage, 인증 증빙의 PDF·JPG·PNG 5MB 제한, 운영자 5분 원본 확인 링크, 튜터 후기 사진과 메시지 이미지 첨부는 내부 구현 기반입니다. 실제 Storage 버킷·정책·운영자 계정에 적용되기 전에는 실제 업로드·열람이 동작하지 않습니다.
- 공공데이터 dry-run과 canonical DB 스키마, 공식 파일 importer는 준비됐지만, 실제 API 승인·키·동기화·운영 데이터 적재는 아직입니다. importer의 공개 후보 규칙도 실제 공식 원본·좌표 경계·운영 검토가 적용되기 전에는 공개 데이터가 아닙니다.
- 서버 AI 사용량 함수는 마이그레이션 적용 뒤에만 동작합니다. 현재 브라우저의 사용량과 플랜 변경은 체험 상태입니다.
- 실제 ADMIN 계정 삭제와 데이터 정리 코드는 서버 전용 서비스 키가 필요합니다. 실제 프로젝트·키·보관 정책을 적용하기 전에는 완료된 삭제 처리로 안내하지 않습니다. demo에서는 브라우저 체험 상태만 사용합니다.
- Stripe Checkout·Customer Portal·구독 상태 API·서명 웹훅(`/api/billing/webhook`)과 DB 상태→AI 권한 반영 코드는 준비됐습니다. 그러나 실제 Stripe 계정·상품/가격·키·웹훅 endpoint와 Supabase 프로젝트·마이그레이션은 아직 연결되지 않아 실제 결제, 청구, 구독 권한 부여는 할 수 없습니다.

## 상용 전환 전 필수 연결

현재 코드는 상용 서비스의 UI·기능 기반이지만, 다음 항목 없이 공개 출시할 수는 없습니다.

- Supabase 프로젝트, Auth, 비공개 Storage와 실제 데이터 연결 및 마이그레이션 적용
- 네이버·카카오·구글 로그인과 공공데이터 API 키
- 동탄1·2 실제 기관 데이터 적재·출처·기준일 검증
- 기관·일터·튜터 후기의 실제 이용 관계 확인, 익명 기준, 교사 후기 3건 공개 기준, 신고·임시조치 운영
- 튜터 신원·자격 증빙의 비공개 Storage, 5MB 파일 제한, 운영자 심사, 보관·삭제 기준
- 학생별 소통의 권한, 읽음·첨부 이미지의 비공개 저장, AI 일지 공유 전 교사 확인
- Stripe 계정·상품/가격을 만들고 `STRIPE_SECRET_KEY`, `STRIPE_UNLIMITED_PRICE_ID`, `STRIPE_WEBHOOK_SECRET`, 서버 전용 `SUPABASE_SERVICE_ROLE_KEY`를 설정. `/api/billing/webhook` endpoint를 Stripe에 등록하고 서명 웹훅으로 무료 10회·유료 무제한 구독을 서버에서 검증
- 이용약관·개인정보처리방침·커뮤니티 정책 초안 3종을 실제 승인 문서로 확정하고, 만 14세 미만 보호자 정책·고객센터 연락처를 확정
- 명칭·상표, 후기·명예훼손, 아동·학생 개인정보, 결제·전자상거래 관련 법률 검토
- 최소 2주 비공개 베타와 운영 절차 검증
