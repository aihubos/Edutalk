# EDU톡 상용 연동 체크리스트

## 현재 상태

완료된 화면·계정/운영 연결 코드와 외부 실운영은 구분한다. 앱은 최초 연령·필수 정책 요약·역할·지역 온보딩, 만 14세 미만의 보호자 전환과 학생 역할 제한, PWA 설치, 브라우저 로컬 저장, AI 초안 체험을 제공한다. 두 홈 경로는 `아이에게 좋은 배움`과 `교육자에게 좋은 일터`다. 실제 Supabase 프로젝트·마이그레이션·Storage·공공 API·OAuth·결제·실운영자 승인·실데이터는 아직 연결되지 않았다. 따라서 지금 공개 상용 출시할 수 없다.

## 1. Supabase

1. local, staging, production 프로젝트를 분리한다.
2. `NEXT_PUBLIC_SUPABASE_URL`과 `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`를 설정한다. 과거의 `NEXT_PUBLIC_SUPABASE_ANON_KEY`는 새 설정에 쓰지 않으며, 기존 프로젝트가 제공하는 legacy anon key는 Supabase 대시보드의 전환 안내를 확인한 뒤 publishable key로 교체한다.
3. `SUPABASE_SERVICE_ROLE_KEY`는 서버 전용 환경변수에만 보관한다.
4. 학생·학습·AI, 튜터·자격증명, 기관 후기, 학부모-교사 소통과 출시 운영 도메인을 포함한 현재 마이그레이션을 먼저 스테이징에 적용하고 실제 역할 계정으로 접근 규칙을 확인한다. 현재 마이그레이션은 어떤 Supabase 프로젝트에도 적용되지 않은 상태다.
5. 공공데이터는 먼저 `pnpm data:sync:dry-run`으로 고정 fixture 정규화와 canonical DB 적재 형식을 확인한다. dry-run은 읽기 전용이며 실제 API 호출·DB 적재·파일 저장을 하지 않는다.
6. 실제 공급자 승인·키가 준비된 뒤 canonical 기관 테이블에만 적재하고, 화면의 체험 fixture를 운영 데이터로 취급하지 않는다.
7. 수동 공식 파일 importer는 UTF-8·CP949 CSV/TSV와 UTF-8 JSON을 받아 학원과 교습소를 별도 유형으로 보존한다. 정상·개원 상태만 공개 후보로 두며, 휴원·폐원·상태 불명은 공개하지 않고 품질 큐에서 확인한다.
8. 반송동·석우동은 동탄1·2 생활권 좌표 경계가 확정되기 전 자동 공개하지 않고 품질 큐로 보낸다. 2026-03-01 이후 과거 `오산동` 표기는 `여울동` 별칭으로 정규화하되, 생활권 판정은 공식 좌표 경계 또는 원본의 명시가 있을 때만 확정한다.
9. 개인정보 없는 제품 이벤트는 브라우저가 DB에 직접 쓰지 않는다. 같은 주소의 `/api/events`가 서버 전용 키로 최소 항목만 저장하며, 서버 키가 없으면 체험 모드로 기록하지 않는다.
10. 운영에서는 `is_synthetic=true` 레코드를 노출하지 않는다.
11. `lib/supabase/*`, `/auth/callback`, 루트 `proxy.ts`와 공식 `@supabase/ssr`·`@supabase/supabase-js` 의존성을 준비했다. 이는 Supabase SSR 계정 기반이며, 환경변수가 비어 있는 현재는 데모 모드다. 프로젝트 URL·publishable key 설정과 실제 공급자 설정 뒤에만 브라우저·서버 클라이언트, OAuth 콜백, 세션 갱신이 동작한다.
12. 마이그레이션에는 가입 직후 프로필·AI 사용량 계정을 만드는 트리거와 무료 10회 또는 활성 무제한 플랜을 원자적으로 판정·차감하는 `consume_ai_credit()` 함수 기반이 들어 있다. 대표 역할은 가입 때 임의로 부여하지 않고 온보딩 완료 시 저장하며, 이용약관·개인정보·커뮤니티 정책 버전은 각 열에 따로 기록한다. 역할별 최소 추천 프로필은 demo에서는 브라우저에, 계정 모드에서는 계정에 저장하고 홈의 demo 추천 이유에만 사용한다. 학생·평가·과목점수·성장기록, AI 일지·생기부, 교사가 발급하는 학생 본인(만 14세 이상)·보호자용 12자리·30분·1회용 연결 코드와 대화방, 메시지·이미지 첨부·알림 읽음, 계정 즐겨찾기, 튜터 프로필·구인·비공개 사진 첨부 후기·문의·지원, 기관 후기 `PENDING`, 신뢰센터·고객센터 요청과 운영자 답변, 탈퇴 요청의 계정 저장 스키마·API도 준비했다. 실제 프로젝트에 적용 전에는 동작하지 않는다.
13. 공개 `GET /api/health`는 앱 상태, 시각, data mode와 Supabase·OpenAI·Stripe·공공데이터의 설정 여부만 반환한다. `?deep=1`은 로그인한 ADMIN만 기능 플래그 수와 최근 동기화 실패 여부를 최소 DB 읽기로 확인한다. 이 상태 확인은 OpenAI·Stripe 같은 외부 서비스를 호출하지 않는다.
14. 저장 검색은 계정별 최대 10개이며 동탄1 또는 동탄2 지역을 명시한 조건만 서버에 저장한다. canonical 기관 검색은 이름·지역·기관 유형과 `NAME`(이름순)·`CHECKED`(최근 확인일순) 조건을 보존한다. 정책·행사는 DATA_OPERATOR·ADMIN이 공식 HTTPS 원문과 기준일을 확인한 뒤 공개한다.
15. AI 초안 생성 API는 사용량 차감 전에 활성 담당 학생 연결을 확인하고 서버의 학생 별칭·학년을 사용한다. 학생별 새 알림장 메시지는 상대방 알림을 생성하고, 보호자 연결 시 해당 학생의 모든 활성 담당 교사와 대화방을 보장한다.
16. 교사 계정은 학생별 확정 `JOURNAL` 초안의 최근 5개만 선택·미리보기한다. 보호자 공유 확인 뒤에만 해당 초안 ID를 `sharedAiDraftId`로 메시지 전송에 포함하며, 계정 연결 실패 시 demo 일지로 바꾸지 않는다.
16. canonical 기관 상세는 공개 승인된 비용·셔틀·모집·프로그램·변경 이력과 생활권·법정동·행정동·주거권·학교·유치원·주거 단지 기준 출발지 거리만 표시한다. DATA_OPERATOR·ADMIN이 출처·확인일·공개 여부와 필드별 확인 주체·신뢰등급을 운영 화면에서 관리하며, 값이 없으면 수치나 생활권을 만들지 않고 `기관 확인 필요`로 표시한다. 기관 공식 답변은 수정 횟수와 최근 수정일만 공개하고 작성자 식별자는 공개하지 않는다.
17. demo와 canonical 기관 목록은 공개 좌표가 있을 때만 위치 도식에 표시한다. 지도 타일·통학시간·이동 경로를 제공하지 않으며, 좌표가 없는 기관은 목록에서 제외하지 않는다.
18. canonical 외부 후기 출처는 DATA_OPERATOR·ADMIN이 확인한 HTTPS 원문 링크, 출처 표기, 확인일, `LINK_ONLY` 또는 `UNAVAILABLE`, 공개 여부만 관리한다. 외부 평점·후기 수·본문·작성자·검색 결과를 수집·스크래핑·저장·합산하지 않고 EDU톡 점수·순위에도 반영하지 않는다. 공개 상세는 승인된 링크만 열고, 링크가 없으면 검색 결과를 원문이나 기관 동일성 확인으로 표시하지 않는다.
17. ADMIN만 서울 기준 월요일에 시작하는 주차로 공개 순위 스냅샷을 확정한다. 같은 주차를 다시 확정하면 기존 스냅샷을 덮어쓰며, 연속 두 회차 이상 있을 때만 현재와 직전 순위를 비교해 상승·하락·신규를 표시한다. 스냅샷이 부족하면 변동을 만들지 않는다. 실제 Supabase 프로젝트와 마이그레이션 적용 전에는 이 운영 연결이 작동하지 않는다.
17. 공개 처리 타임라인은 정정의 `APPROVED`·`REJECTED`·`CANCELLED` 및 기관 자체 대상 신고의 `TEMPORARILY_HIDDEN`·`UPHELD`·`RESTORED`·`CLOSED` 결과와 처리일만 표시한다. 대기·검토·보완 요청, 후기 대상 신고, 신청자·작성자·운영자, 증빙, 원문과 처리 메모는 공개하지 않는다.
16. 인증 요청이 승인·반려·취소되면 증빙 원본에 30일 보관 만료일을 기록한다. 실제 운영에서는 예약 작업이 ADMIN 전용 `/api/admin/verification-retention` 삭제 경로를 실행하고 결과를 운영 기록에 남겨야 한다.

## 2. 계정·권한

1. Supabase가 설정된 상용 모드의 순서는 `로그인 → 약관·연령 확인 → 대표 역할·지역 선택 → 최소 프로필 입력 → 홈`으로 유지한다. 로그인 뒤에도 온보딩을 완료하기 전에는 홈으로 보내지 않는다.
2. Supabase가 미설정된 demo 모드는 계정 없이 `연령·정책 요약·역할·지역 선택 → 홈`의 체험 온보딩만 제공한다. demo의 브라우저 저장 상태를 실제 계정이나 동의 기록으로 취급하지 않는다.
3. 온보딩의 정책 요약은 정식 약관·개인정보처리방침을 대체하지 않는다. 상용 모드에서는 승인된 정식 문서와 동의 기록을 연결한다.
4. 만 14세 미만은 보호자 아래 자녀 프로필로만 처리하고 학생 역할 직접 선택을 서버에서도 제한한다.
5. Google·Kakao·이메일 로그인 UI와 Supabase SSR 계정 연결 기반은 준비됐지만, 실제 공급자 설정과 로그인 검증은 아직이다. 네이버는 OIDC 공급자가 아직 연결되지 않아 상용 로그인 수단으로 제공하지 않는다.
6. 네이버·카카오·구글 OAuth를 스테이징에서 각각 설정·검증한 뒤에만 공개한다.
7. 역할은 사용자가 바꾸는 metadata가 아닌 DB의 `user_roles`로 관리한다.
8. 교사가 학생을 직접 등록하는 절차와 부모·학생·담당 교사 연결 승인을 만든다. 학생 기록은 활성 연결이 있는 본인·보호자·담당 교사만 읽는다.
9. 선생님만 성적·성장·AI 초안을 추가하고, 학부모와 학생은 열람만 한다. AI 학생일지 공유는 교사 확인 뒤에만 전송한다.
10. 학생별 알림·메시지는 해당 교사와 보호자만 접근하게 하고, 읽음·중요·이미지 첨부는 비공개로 저장한다. 메시지 이미지 첨부는 Storage가 연결되기 전에는 demo 브라우저 체험일 뿐 실제 전송 파일이 아니다.
11. 교사가 발급하는 보호자 또는 학생 본인(만 14세 이상) 연결은 12자리, 30분 유효, 1회 사용 코드로만 시작하고 연결 뒤 학생별 대화방을 만든다. 코드 생성·소비와 대화방 생성은 실제 프로젝트 적용 뒤에만 운영 데이터가 된다.

## 2-1. 게스트 공개 범위와 개인 기능 경계

1. 비로그인 게스트는 홈, 기관찾기, 기관 상세, 랭킹, 튜터, 정책·행사, 기관 비교만 공개 경로로 이용하게 한다. 공개 경로도 demo fixture를 실제 운영 데이터로 보이게 하지 않는다.
2. 성적관리, AI 학생일지·생기부, 메시지, 후기 작성, 인증·정보정정·신고, MY는 개인 경로다. 온보딩을 완료하지 않은 게스트는 `/login`으로 보낸다.
3. 게스트 내비게이션은 공개 경로와 로그인·체험 시작만 보여준다. 개인 기능 링크와 개인 상태 알림은 게스트 메뉴에서 노출하지 않는다.
4. 운영 관리자 화면은 production 내비게이션에 노출하지 않는다. demo에서만 별도 체험 화면으로 확인하며, 실제 운영 권한이나 처리 결과를 뜻하지 않는다.

## 3. AI·구독

1. AI 호출 전 서버에서 `ai_usage_accounts`를 원자적으로 차감한다.
2. 무료는 계정당 누적 10회다. Stripe Checkout·Customer Portal 진입 API와 계정 구독 상태 조회 API 코드는 준비했다. 유료 무제한은 Stripe 서명 웹훅으로 확인된 `ACTIVE` 기간에만 통과시키며, 브라우저의 플랜 변경은 demo 체험 상태일 뿐 실제 구독이 아니다.
3. 서버는 결제사 상태를 `ACTIVE`, `PAST_DUE`, `CANCELED`로만 저장·표시한다. 검증된 `billing_subscriptions` 상태는 `ai_usage_accounts`에 반영되고, `ACTIVE`만 무제한 권한을 주며 나머지는 무료 한도를 적용한다.
4. 실제 연결에는 서버 전용 `STRIPE_SECRET_KEY`, `STRIPE_UNLIMITED_PRICE_ID`, `STRIPE_WEBHOOK_SECRET`, `SUPABASE_SERVICE_ROLE_KEY`가 필요하다. 이 값은 브라우저 환경변수에 두지 않는다.
5. Stripe Dashboard에 실제 상품·가격을 만들고 `/api/billing/webhook` endpoint를 등록한다. Checkout 또는 Portal 복귀 화면이 아니라 이 endpoint의 서명 웹훅만 활성 구독과 AI 권한을 결정한다.
6. 현재는 Stripe 계정·상품/가격·키·웹훅 endpoint와 Supabase 프로젝트·마이그레이션이 모두 미연결이다. 따라서 Checkout·Customer Portal·웹훅 코드가 있어도 실제 결제, 청구, 구독 권한 부여는 할 수 없으며 공개 상용 출시도 불가하다.
7. OpenAI 응답 저장은 `store: false`를 유지하고 실명 대신 별칭을 사용한다.

## 4. 기관·일터·튜터 후기와 순위

1. 어린이집정보공개·유치원알리미·나이스의 이용 승인과 API 키를 받는다. API URL은 공급자별 계약·승인 문서에서 확정한 뒤 `*_API_URL`에만 설정하며, 코드에서 추측하지 않는다.
2. `pnpm data:sync:dry-run`은 고정 fixture를 정규화하고 공급자별 JSON 보고서만 표준 출력으로 보여준다. DB·Storage·파일 쓰기는 하지 않는다. 실제 URL을 읽는 `--live` 모드도 명시적으로 설정된 URL·키가 모두 있을 때만 사용하며, 계속 읽기 전용이다.
3. 기관명·주소·좌표 중복을 정규화하고 출처와 기준일을 보존한다.
4. 학생·학부모·교육자 평점은 별도 점수로 저장·표시하며 어떤 평균이나 순위에도 서로 섞지 않는다.
5. 기관 공개 점수는 승인된 후기 숫자만 집계한다. 교육자 일터 후기는 작성자 공개 정보를 숨기고, 실제 관계 확인을 거친 승인 교사 후기 3건 이상일 때만 공개 점수를 계산한다.
6. 학생 후기는 시간대(`scheduleFit`), 학교에서 이동(`schoolCommute`), 수업 분위기, 숙제 부담, 반 인원, 설명 방식, 레벨테스트 도움, 또래 구성, 자습공간, 시험대비의 10개 핵심 항목과 이해도·수업 속도·동기·이동 편의의 4개 학습 체감 보조 항목, 총 14개를 모두 받는다. 이전 후기에서 없는 항목은 0점으로 채우지 않는다.
7. 기관·일터·튜터 순위는 광고 판매·노출 대가와 분리한다. 기관·일터 순위는 권역과 기관 유형으로 좁힐 수 있고 각 항목은 공개 기관 상세로 연결한다. 실제 운영 전에는 산식, 동점 처리, 최신성, 신고·임시숨김 정책을 공개한다.
8. 로그인한 학부모에게는 관계 인증 전에도 승인 학부모 후기의 장점만 최대 2건, 각 180자 이내로 베타 미리보기로 제공한다. 개선점·추천 대상·상세 내용은 유효한 관계 인증 뒤에만 열며, 미리보기는 외부 실데이터 연결을 뜻하지 않는다.
9. 네이버 지도·카카오맵·인스타그램 평점은 합법적으로 이용 가능한 공식 제공 계약이 확인되기 전에 수집·합산하지 않는다. 외부 후기는 출처별 원문 링크로만 두고 EDU톡 확인 후기만 내부 평점·순위에 사용한다.
10. 튜터는 신원과 자격 증빙을 강하게 요청하고, 증빙 원본은 비공개 Storage와 심사자 접근으로 제한한다. 공개 화면에는 검증 상태와 필요한 최소 정보만 표시한다.
11. 튜터 후기는 본인·자격 인증을 마친 튜터가 발급한 12자리·7일·1회용 수업 확인 코드로만 접수한다. 코드 원문은 저장하지 않고 digest만 보관하며, 평점은 0.5점 단위다. 후기는 운영자 `APPROVED` 전까지 비공개이고, 응답률은 튜터가 입력하지 않으며 튜터에게 온 계정 문의에 직접 답변한 비율로만 계산한다. 구인글 지원에 대한 채용 주체의 응답은 튜터 응답률에 포함하지 않는다.
12. 기관 관계 신청에서 교육자 후기·관계 인증 등과 이해관계 충돌이 감지되면 자동 승인하지 않고 `CONFLICT_REVIEW` 별도 검토 상태로 둔다.
13. 튜터와 구인글은 표시명·과목·소개·활동 동네, 그리고 제목·본문·과목·지역을 공통 검색어로 찾는다. 계정 모드에서는 서버 목록만, demo에서는 체험 목록만 대상으로 하며 실패 시 체험 데이터로 바꾸지 않는다.

## 5. 파일·운영

1. 인증·기관 정보 정정·콘텐츠 신고·탈퇴·고객센터 요청은 계정별 접수·본인 조회·상태 이력 코드가 준비되어 있다. 기관 후기와 튜터 후기는 각각 `PENDING` 또는 심사 대기 상태로 접수할 기반이 있다. 실제 operator role과 운영자 콘솔/API는 증빙 필수 인증 승인·반려, 승인 관계 인증의 역할별 6개월 열람권 부여, 승인 후기 처리, 고객센터·튜터 문의 답변을 위한 내부 구현이다. 실제 프로젝트·운영자 계정에 적용되기 전에는 운영 처리 결과가 아니다.
2. 인증 증빙은 비공개 Storage에서 PDF·JPG·PNG만, 파일당 5MB 이하로 처리한다. 운영자는 메타데이터와 5분 만료 signed URL로 원본을 확인한다. 튜터 후기 사진과 메시지 이미지도 공개 URL이 아닌 비공개 객체 경로로 다루며, DB에는 원본 파일명·민감한 문서 내용 대신 필요한 최소 메타데이터만 남긴다.
3. 인증 문서 업로드, 심사자 권한, 보완 요청, 승인 뒤 역할별 6개월 열람권 부여는 서버 작업으로 연결한다. Storage가 미연결인 현재는 인증 문서·튜터 후기 사진·메시지 이미지를 실제로 업로드하거나 전송한 것처럼 안내하지 않는다.
4. 계정 알림은 인증·후기 상태 변경, 고객센터·튜터 문의 답변, 학생별 메시지, 관심 기관의 승인 후기·공식 답변·모집 변경, 저장 검색의 신규 기관에서 자동 생성한다. 이용자는 본인 알림 읽음과 종류별 수신 여부를 계정에 저장한다. 설정 행이 없으면 기본 수신하며, 이메일·푸시 발송은 아직 연결하지 않는다.
5. 신고·임시조치·기관 정정·기관 공식 답변·삭제 요청·감사 기록 운영 흐름을 연결한다. canonical 공개 상세의 정정·기관 대상 신고 타임라인은 안전한 처리 결과와 날짜만 공개하며, 대기 요청·원문·식별자·증빙은 공개하지 않는다. 동기화 실행과 데이터 품질 이슈는 서비스 계정 작업으로만 기록한다.
6. MY의 즐겨찾기는 demo에서는 브라우저 localStorage에, Supabase 계정 모드에서는 계정별 `institution_favorites`에 저장·삭제한다. 계정 비교 목록은 공개 canonical 기관만 최대 3곳 저장한다. 보호자 자녀 프로필은 별칭·학년만 다루며 실명·학교명·생년월일을 받지 않는다. 탈퇴 요청은 demo에서는 브라우저 localStorage에, Supabase 계정 모드에서는 `account_deletion_requests`에 `PENDING` 또는 `PROCESSING` 상태로 저장·조회한다. ADMIN의 실제 계정 삭제와 관련 데이터 정리는 서버 전용 서비스 키가 있을 때만 실행한다. 실제 프로젝트·키·보관 정책을 적용하기 전에는 완료된 삭제 처리로 안내하지 않는다. 고객센터는 demo localStorage 또는 계정 `support_requests` 접수·조회와 운영자 답변 저장을 제공하며, 이메일 발송은 미연결이다.
7. ADMIN 기능 플래그는 AI 생성·후기 제출·튜터 쓰기·결제 진입·공공기관 탐색을 서버에서 중지할 수 있다. DATA_OPERATOR/ADMIN은 동기화 실행과 품질 이슈를 확인하고, ADMIN은 최근 운영 지표·축약된 감사 이력·연결 상태와 주간 순위 확정을 확인한다. 이 화면은 실제 프로젝트와 운영 역할 연결 뒤에만 운영 근거가 된다.
8. 이용약관·개인정보 처리방침·커뮤니티 정책은 출시 전 검토 초안 3종만 준비되어 있다. 만 14세 미만 보호자 정책·고객센터 연락처와 함께 승인된 정식 문서로 확정·공개한다.
9. 후기·명예훼손, 아동·학생 개인정보, 익명 일터 후기, 증빙 보관, 결제·전자상거래의 법률·정책 검토를 끝낸다.
10. 스테이징 점검 후 2주 비공개 베타를 거쳐 공개 출시한다. 이 조건들이 충족되기 전에는 공개 상용 서비스로 안내하거나 실제 점수·순위를 노출하지 않는다.
11. PWA의 정적 offline fallback은 연결 실패 때 이미 본 공개 화면을 일부 보여 주는 용도다. 로그인·저장·후기·메시지·결제는 오프라인에 저장·전송된 것으로 안내하지 않으며, 연결 뒤 사용자가 다시 제출한다.
12. 설치 버튼은 지원 브라우저의 설치 요청을 먼저 사용하고, iOS Safari에는 공유 → 홈 화면에 추가를, 그 외 브라우저에는 앱 설치 또는 홈 화면에 추가 경로를 안내한다. 설치 자체가 계정 연결이나 공개 범위를 바꾸지 않는다.
13. demo 기관 상세의 신뢰 카드는 hero 바로 뒤에 먼저 보이도록 배치한 체험 UI다. 실제 canonical 신뢰 정보와 운영 결과는 Supabase·공식 데이터 적용 뒤에만 근거가 된다.
