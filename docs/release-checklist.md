# EDU톡 단계적 출시 체크리스트

이 문서는 실제 제공자 프로젝트와 배포 환경을 연결한 뒤 운영자가 실행할 절차다. 현재 Supabase, Storage, Stripe, 공공 API, OAuth, 모니터링과 배포 연결은 완료된 상태가 아니다. 이 문서가 있다는 이유만으로 공개 출시를 시작하지 않는다.

## 시작 전

- [ ] `docs/release-evidence.example.json`을 실제 비공개 운영 기록 위치에 복사하고 담당자·날짜·증빙 경로를 기록한 뒤 `RELEASE_EVIDENCE_FILE`로 지정한다. 이 파일에는 비밀키나 개인정보를 넣지 않는다.
- [ ] 운영 환경값과 release evidence 파일을 사용해 `pnpm release:check`를 실행하고 모든 항목이 `ready: true`인지 확인한다. 환경값만 `true`로 바꿔서는 법률·베타·백업·모니터링·공식 데이터 게이트가 통과하지 않는다.
- [ ] 정식 이용약관·개인정보처리방침·커뮤니티 정책과 후기·아동 개인정보·결제 관련 법률 검토가 끝났다.
- [ ] 2주 비공개 베타를 완료하고, 운영자·지원 담당자와 중단 결정 담당자를 정했다.
- [ ] staging과 production을 분리하고, 실제 환경변수·마이그레이션·Storage·OAuth·결제 웹훅을 적용했다.
- [ ] 이전 배포로 되돌리는 방법과 DB 변경의 전방호환 여부를 확인했다.
- [ ] 기능별 feature flag의 켜기·끄기 담당자와 사용자 안내 문구를 준비했다.

## 각 단계에서 공통으로 볼 것

- [ ] 기본 health와 deep health가 정상인지 확인한다. 실제 경로와 확인 방법은 연결한 배포 환경의 운영 기록을 따른다.
- [ ] 오류 증가, 응답 지연, 로그인 실패, 저장 실패를 관찰한다.
- [ ] 핵심 흐름을 확인한다: 로그인·온보딩, 기관 탐색, 인증·후기 접수, 학생 기록, 메시지, 고객센터, 운영자 처리, 구독 상태 표시.
- [ ] demo 데이터가 production 공개 화면에 섞이지 않는지 확인한다.
- [ ] 비공개 증빙·학생 정보·첨부 파일이 권한 없는 화면에 보이지 않는지 확인한다.
- [ ] 이상이 있으면 다음 단계로 가지 않고 feature flag로 해당 기능을 제한하거나 이전 배포로 복구한다.

## 단계별 진행

### 1. Staging

- [ ] 실제와 분리된 계정으로 health/deep health와 핵심 흐름을 확인한다.
- [ ] 마이그레이션이 이전 앱 버전과 함께 동작하는지 확인한다.
- [ ] Stripe, OpenAI, Supabase, 공공 API 오류가 나면 사용자 안내만 표시되고 잘못된 성공 상태가 나오지 않는지 확인한다.
- [ ] 통과 기준을 기록한 뒤 팀 검토 단계로 간다.

### 2. 팀 내부

- [ ] 제한된 팀 계정만 허용한다.
- [ ] 운영 콘솔의 인증·후기·신고·정정·지원·탈퇴 처리와 알림을 확인한다.
- [ ] 장애·되돌리기 절차를 실제로 한 번 연습한다.

### 3. 5%

- [ ] 대상 사용자를 제한해 열고, 오류·지연·핵심 흐름을 관찰한다.
- [ ] 새 문의와 신고의 처리 기한을 지킬 수 있는지 확인한다.
- [ ] 중단 기준이 없으면 25%로 확장하지 않는다.

### 4. 25%

- [ ] 5% 단계의 문제와 지원 요청이 해결됐는지 확인한다.
- [ ] 인증·후기·순위·기관 비교·메시지·AI 사용량의 실제 데이터 경계를 재확인한다.

### 5. 50%

- [ ] 운영자 처리량, Storage 사용량, 외부 API 한도, 결제 웹훅 지연을 확인한다.
- [ ] 오류나 지연이 늘면 확대를 멈추고 이전 안정 단계로 되돌린다.

### 6. 100%

- [ ] 각 단계의 기록과 중단 기준 충족 여부를 확인한 뒤 전체 공개를 승인한다.
- [ ] 전체 공개 뒤에도 같은 관찰 항목과 feature flag를 유지한다.

## 즉시 중단 기준

- 개인정보·학생 기록·비공개 증빙이 잘못 노출될 가능성
- 로그인·권한·저장 실패가 핵심 흐름을 막는 경우
- 공개 후기·순위·기관 정보에 demo 또는 잘못된 데이터가 노출되는 경우
- Stripe 웹훅 확인 없이 유료 권한이 생기거나 결제 상태가 잘못 표시되는 경우
- 오류·지연이 운영자가 정한 허용 범위를 넘거나, 지원·신고 처리 기한을 지킬 수 없는 경우

중단 시 새 확대를 멈추고, 영향을 받은 기능을 feature flag로 끈 뒤 [되돌리기 계획](./rollback-plan.md)을 따른다. 확인되지 않은 원인이나 타인의 정보는 사용자 공지에 포함하지 않는다.
