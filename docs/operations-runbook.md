# EDU톡 출시 운영 매뉴얼

이 문서는 제공자 프로젝트를 실제로 연결한 뒤 운영자가 수행할 체크리스트다. 현재 Supabase, Storage, Stripe, 공공 API와 모니터링은 연결·운영 중인 상태가 아니다. 연결 전에는 공개 상용 서비스를 열지 않는다.

## 매일 시작 전

- [ ] 운영자 콘솔에서 새 인증, 기관 후기, 튜터 후기, 신고, 정보 정정, 고객센터, 탈퇴 요청을 확인한다.
- [ ] 공개 순위·기관 정보가 demo fixture가 아닌 canonical 공개 데이터인지 확인한다.
- [ ] Supabase, Stripe, OpenAI, 공공 API의 장애 안내가 필요한지 확인한다.
- [ ] 로그에는 후기 원문, 증빙 파일명, 상세 위치, 계정 식별자, 학생 정보, 원본 링크를 적지 않는다. 요청 ID도 운영 화면 밖으로 복사하지 않는다.

## 권장 처리 기한

- 개인정보·신원 노출 위험 신고: 접수 즉시 확인하고, 위험이 있으면 먼저 `TEMPORARILY_HIDDEN` 처리한다.
- 일반 콘텐츠 신고: 영업일 1일 안에 `TRIAGED` 또는 보완 요청 상태로 바꾼다.
- 인증·후기·정보 정정: 영업일 3일 안에 승인, 반려 또는 보완 요청을 남긴다.
- 고객센터·튜터 문의: 영업일 2일 안에 첫 답변을 남긴다.
- 탈퇴 요청: 보관 정책과 연결 데이터 영향 확인 뒤 영업일 7일 안에 처리 또는 사유를 남긴다.

기한을 지키지 못하면 상태를 먼저 갱신하고, 고객에게 가능한 다음 확인 시점을 안내한다.

## 인증과 후기

- [ ] 인증 요청: 제출 메타데이터와 관계·자격 요건을 확인한다. 증빙 원본을 내려받거나 외부로 전달하지 않는다.
- [ ] 증빙 원본 확인: 운영자 권한으로만 5분 만료 링크를 열고, 접근 사유를 내부 처리 메모에 짧게 남긴다. 링크를 채팅·이메일·문서에 복사하지 않는다.
- [ ] 보완 필요 시: 필요한 항목만 설명하고 민감정보를 다시 요구하지 않는다.
- [ ] 기관·튜터 후기: 근거와 정책을 확인해 승인·반려·임시숨김을 선택한다. 승인된 후기만 공개 집계와 순위에 반영된다.
- [ ] 작성자가 후기를 내린 경우: 보관 상태는 유지하되 공개 본문·집계·랭킹·공식 답변에서 제외되는지 확인한다. 관리자 심사 기록은 삭제하지 않는다.

## 신고와 임시 조치

- [ ] 신고 대상, 신고 사유, 현재 공개 영향만 확인한다. 신고자·작성자의 신원은 운영 메모에 적지 않는다.
- [ ] 개인정보, 식별 위험, 심각한 피해 우려는 우선 `TEMPORARILY_HIDDEN`으로 처리한다.
- [ ] 추가 자료가 필요하면 `REQUESTED_MORE_INFO`, 검토 중이면 `TRIAGED`로 상태를 남긴다.
- [ ] 조치가 타당하면 `UPHELD`, 문제가 없으면 `REJECTED`, 임시 조치 해제는 `RESTORED`, 종료는 `CLOSED`를 사용한다.
- [ ] 복원 전에는 신고 사유가 해소됐는지와 관련 후기·공개 집계 영향만 다시 확인한다.

## 기관 정보 정정과 기관 멤버

- [ ] 정정 요청은 현재 정보와 제안 정보, 공공 출처·기준일을 비교한다.
- [ ] 확인 전에는 `PENDING` 또는 `NEEDS_INFO`, 반영 가능하면 `APPROVED`, 근거가 없으면 `REJECTED`를 사용한다.
- [ ] 승인 후 실제 canonical 데이터 반영은 별도 데이터 운영 절차에서 한다. 요청 승인만으로 공개 정보가 자동 변경된다고 안내하지 않는다.
- [ ] 기관 멤버는 기관 소속·대표 권한을 확인한 뒤 승인한다. 멤버 승인과 후기 작성자 신원 열람 권한은 별개다.

## 지원과 탈퇴

- [ ] 고객센터·튜터 문의 답변은 요청 내용에 필요한 범위만 쓰고 이메일 발송 여부를 실제로 확인하기 전에는 발송됐다고 안내하지 않는다.
- [ ] 탈퇴 요청은 ADMIN만 최종 처리한다. 학생·보호자·교사 연결, AI 초안, 대화, 증빙, 보관 의무를 확인하고 처리 메모를 남긴다.
- [ ] 서비스 키 또는 보관 정책이 준비되지 않았으면 실제 삭제를 실행하지 않고 상태와 이유를 안내한다.

## 데이터·외부 서비스 장애

- **공공 데이터 ETL:** 먼저 `pnpm data:sync:dry-run` 결과에서 정규화·중복·기준일 문제를 확인한다. write 실행은 승인된 운영자와 실제 키가 있을 때만 하며, 완료 후 canonical 공개 여부를 따로 확인한다.
- **Supabase/Storage 장애:** 계정 저장·증빙·이미지 업로드가 불가하다는 안내를 표시하고, 브라우저 demo 상태를 실제 요청으로 바꾸지 않는다.
- **Stripe 장애:** Checkout·Portal을 비활성화하거나 오류 안내를 유지한다. 결제 완료 화면만으로 권한을 주지 않고 `/api/billing/webhook`의 서명 이벤트 확인을 기다린다.

## 주간 순위 확정

- [ ] 실제 Supabase 프로젝트와 마이그레이션이 적용되고 ADMIN 역할로 로그인한 상태인지 확인한다. 현재 연결 전에는 이 절차를 실행하거나 순위를 확정한 것으로 안내하지 않는다.
- [ ] 서울 기준 월요일 시작 주차를 확인하고, 승인 후기·canonical 공개 기관만 대상인지 확인한다.
- [ ] ADMIN만 해당 주차의 순위를 확정한다. 같은 주차를 다시 확정할 때는 새 항목을 추가하는 대신 기존 스냅샷을 덮어쓴다는 점을 확인한다.
- [ ] 연속된 두 주차 스냅샷이 있을 때만 상승·하락·신규 표기를 공개한다. 한 회차뿐이면 변동 표기를 만들지 않는다.
- **OpenAI 장애:** AI 생성 기능을 feature flag로 중지하고, 사용자가 작성한 관찰 사실을 보존한 채 재시도 안내를 표시한다.
- [ ] 장애 종료 후에는 기능을 단계적으로 다시 켜고, 영향을 받은 요청의 상태·알림만 재확인한다.

## 출시 판단

- [ ] 정식 이용약관·개인정보처리방침·커뮤니티 정책, 후기·아동 개인정보·결제 관련 법률 검토가 끝났다.
- [ ] 실제 프로젝트·마이그레이션·Storage·OAuth·공공 API·Stripe 웹훅이 연결됐다.
- [ ] 운영자 역할, 문의 채널, 임시숨김·복원 담당자와 백업 담당자가 정해졌다.
- [ ] 2주 비공개 베타와 아래 복원 리허설을 완료했다.

하나라도 미완료면 공개 상용 출시를 하지 않는다.
