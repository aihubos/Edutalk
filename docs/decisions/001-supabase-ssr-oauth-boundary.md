# ADR 001: Supabase SSR과 OAuth 공급자 경계

- 날짜: 2026-08-13
- 상태: Accepted for implementation

## 배경

EDU톡에는 로그인, 계정별 학생 기록, 후기, 운영 요청처럼 개인별로 분리해야 하는 기능이 있다. 브라우저에 중요한 서버 권한을 두지 않고, 로그인 상태를 화면과 서버에서 일관되게 다룰 필요가 있다.

## 결정

- Supabase SSR 기반의 브라우저·서버 클라이언트와 세션 갱신 흐름을 사용한다.
- 로그인 공급자는 Supabase 설정 뒤에만 실제로 사용한다. Google·Kakao·이메일은 공급자 설정과 검증 후 제공한다.
- 네이버 로그인은 OIDC 연결이 완료되기 전에는 안내만 표시한다.
- 서버 전용 키와 결제·운영 권한은 브라우저에 두지 않는다.

## 결과

- 설정이 없는 환경은 계정 없이 demo 온보딩과 브라우저 체험 상태를 사용한다.
- 설정된 계정 모드는 로그인 뒤 약관·연령·대표 역할·지역·최소 프로필을 마친 뒤 개인 기능을 이용한다.
- 로그인 화면이 있어도 공급자 설정이 끝나기 전에는 실제 상용 로그인으로 안내하지 않는다.

## 외부 미연결 항목

실제 Supabase 프로젝트, 환경변수, OAuth 공급자 설정, 이메일 발송 설정, 네이버 OIDC 연결은 아직 완료된 상태가 아니다.
