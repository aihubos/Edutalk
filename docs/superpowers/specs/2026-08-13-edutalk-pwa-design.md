# EDU톡 PWA MVP 설계

## 목표

외부 계정 없이도 즉시 실행하고 핵심 흐름을 확인할 수 있는 모바일 우선 PWA `demo`를 만든다. 첫 화면은 `아이에게 좋은 배움`과 `교육자에게 좋은 일터`로 나뉜다. Supabase, OAuth, 공공데이터 키가 준비되면 화면을 다시 만들지 않고 연결부를 교체할 수 있게 설계한다. 이는 공개 상용 서비스가 아니다.

## 이번 실행본의 경계

### 포함

- 학부모, 학생, 선생님 역할 전환
- 아이·학부모의 기관 탐색과 교육자의 일터 탐색을 나눈 두 홈 경로
- 홈, 기관 찾기, 검색과 필터, 기관 상세
- 즐겨찾기, 최대 3개 비교
- 후기 작성 단계와 로컬 임시 저장, 익명 교육자 일터 후기
- 교육자 일터 공개 점수는 확인된 후기 최소 3건부터라는 화면 원칙
- 학생·학부모·교육자 점수를 섞지 않는 상세·순위와 광고 없는 기관·일터·튜터 순위
- 인증 요청 상태 안내
- MY, 알림, 개인정보 메뉴
- 설치형 PWA 기본 구조
- 관리자용 운영 현황 화면
- 교사가 직접 등록한 학생 ID별 내신·모의고사·수능형 성적 및 성장기록 그래프
- 선생님 전용 AI 학생일지·생기부 검토용 초안, 교사 확인, 계정당 무료 10회·유료 무제한 플랜 미리보기
- 개인 튜터 탐색, 튜터 프로필·구인글 등록, 사진 후기·평점·순위
- 튜터 신원·자격 증빙 요청과 증빙 원본의 비공개 심사 원칙
- 학생별 학부모-교사 알림·메시지, 읽음·중요 표시·이미지, 교사 확인 뒤 AI 학생일지 공유
- 네이버 블로그·지도, 카카오맵, 인스타그램 외부 후기의 출처별 원문 연결만 제공
- 역할별 교육 정책·프로그램·행사 큐레이션
- 통학차량·체험수업 필터, 설명회·레벨테스트·특강, 즉시 문의
- 체험 데이터와 운영 데이터의 명확한 구분

### 외부 준비 후 연결

- 네이버, 카카오, 구글 실제 OAuth
- Supabase DB, 비공개 Storage, 운영 권한
- 동탄 공공데이터 실제 적재와 주기 동기화
- 증빙 파일 실제 업로드와 관리자 심사
- 실제 이용 관계 확인, 익명 후기 공개 기준, 후기 3건 최소 기준의 서버 강제
- 실제 결제·구독 검증, 학부모-교사 소통 권한·첨부파일 저장
- 이메일, 푸시, 오류 관측

화면은 외부 연결 상태를 숨기지 않는다. 로컬 데이터는 모든 레코드에 `isSynthetic: true`를 두고, 화면에 체험용임을 표시한다.

## 사용자 흐름

1. 사용자는 홈에서 동탄1, 동탄2 또는 전체를 고른다.
2. 기관 유형을 누르거나 검색창을 사용한다.
3. 기관 목록에서 필터와 정렬을 적용한다.
4. 기관 상세에서 출처, 비용, 학생·학부모·교육자별 분리 점수와 후기 미리보기를 확인한다.
5. 기관을 저장하거나 최대 3개까지 비교한다.
6. 교육자 일터 후기는 관계 선택, 인증 안내, 구조화 평가, 내용 작성, 제출 확인 순서로 진행하고 공개 작성자 정보는 익명으로 처리한다. 공개 점수는 확인 후기 3건 이상일 때만 계산한다.
7. 교사는 학생을 직접 등록해 성적·성장기록과 AI 초안을 남기고, 확인한 AI 학생일지만 해당 학부모에게 공유한다.
8. MY에서 역할을 바꾸면 홈 문구와 메뉴가 즉시 달라진다.

## 화면 구조

- `/`: `아이에게 좋은 배움`·`교육자에게 좋은 일터` 선택 홈
- `/discover`: 기관 검색, 필터, 정렬, 빈 결과
- `/institutions/[id]`: 기관 상세, 저장, 비교, 후기 요약
- `/compare`: 최대 3개 비교
- `/review`: 단계형 후기 작성
- `/activity`: 저장 기관과 인증 현황
- `/my`: 역할 전환과 계정 메뉴
- `/onboarding`: 역할과 지역 선택
- `/admin`: 운영 큐 요약
- `/student-records`, `/student-records/[id]`: 역할별 학생 목록과 성적·성장 상세
- `/teacher-log`: AI 학생일지
- `/school-record`: AI 생기부 검토용 초안
- `/subscription`: 무료 10회·무제한 플랜 상태
- `/tutors`, `/tutors/[id]`: 튜터·구인·사진 후기
- `/policies`: 역할별 공식 정책·행사 출처
- `/messages`: 학생별 학부모-교사 알림·메시지

## 구조

- Next.js App Router와 TypeScript를 사용한다.
- 사용자 상태는 React Context로 관리하고 로컬스토리지에 저장한다.
- 데이터 접근은 `lib/repository` 인터페이스 뒤에 둔다.
- 지금은 로컬 fixture 구현을 사용한다. Supabase 마이그레이션에는 학습, 튜터·자격 증명, 기관 후기, 소통 스키마가 준비되어 있으나 프로젝트 연결과 적용은 아직이다.
- 역할별 차이는 하나의 메뉴 설정과 콘텐츠 규칙에서 계산한다.
- UI는 작은 공통 컴포넌트로 나누고 모든 시각 값은 `DESIGN.md` 토큰을 사용한다.

## 오류와 상태

- 검색 결과 없음: 필터 초기화 제공
- 비교 3개 초과: 현재 선택을 유지하고 안내 토스트 표시
- 후기 미완료: 다음 버튼 비활성화와 해당 단계 안내
- 브라우저 저장 실패: 메모리 상태는 유지하고 새로고침 시 초기화될 수 있음을 안내
- 외부 연결 없음: 실패처럼 보이지 않게 `체험 모드` 상태로 표시
- 오프라인: 이전에 방문한 앱 셸을 보여주고 네트워크 필요 기능을 안내

## 완료 기준

- `pnpm dev`로 즉시 실행된다.
- `pnpm build`가 성공한다.
- 390px에서 가로 스크롤 없이 핵심 흐름을 완료한다.
- 768px과 1280px에서 모바일 내용을 단순 확대하지 않고 여백과 열 구조가 자연스럽다.
- 키보드 포커스가 보이고 모든 터치 대상이 44px 이상이다.
- 역할, 즐겨찾기, 비교, 후기 초안이 새로고침 후 유지된다.
- 학생·성적·성장·AI 초안·튜터 로컬 등록 데이터가 학생//사용자 ID로 구분된다.
- 모든 체험 데이터는 운영 데이터처럼 오인되지 않는다.
- 교육자 일터의 공개 점수는 확인 후기 3건 미만일 때 표시하지 않으며, 학생·학부모·교육자 점수는 절대 합산하지 않는다.
- 외부 후기는 원문 출처 링크만 제공하고 내부 점수·순위에 합산하지 않는다.
- 튜터 증빙과 학생 소통 첨부물은 실제 연동 때 비공개 저장·권한·삭제 정책이 없으면 공개하지 않는다.

## 공개 상용화 전제

현재 화면과 로컬 데이터만으로는 공개 상용화할 수 없다. 실제 계정·DB·비공개 파일 저장·결제 검증·공공데이터·운영자 심사와 함께, 익명 일터 후기·명예훼손, 학생·아동 개인정보, 튜터 증빙 보관, 순위 공정성의 정책·법률 검토가 필요하다.
